2

A real robot: the self-driving car

A self-driving car is a robot on wheels. Every sensor in the picture is a node, and the onboard computer runs dozens more (perception, planning, control). They talk in exactly these three ways.

📻
Topics: the sensors stream
nonstop, many times per second
  • LIDAR → /lidar/points
  • Camera → /camera/image
  • Radar → /radar/objects
  • GPS → /gps/fix
  • Wheel encoder → /wheel/odom
  • Computer → /cmd_vel (steer, throttle)
🛎️
Services: quick questions
one request, one answer
  • "Reset the trip odometer" → "done"
  • "Switch the headlights on" → "on"
  • "Calibrate the camera" → "OK"
  • "Which driving mode?" → "auto"
🎯
Actions: long jobs
goal → feedback → result, cancellable
  • "Drive to the university" → "4.2 km… 1.1 km… arrived"
  • "Park in bay 7" → "reversing… 0.5 m… parked"
  • Passenger presses stop → the goal is cancelled

4.1Services, step by step

1Picture it2The rules3Watch it4Try it5Remember it
1

Picture it: the help desk

🛎️

A service is like a help desk. You walk up (you are the client), ask one question (the request), and the person behind the desk (the server) gives you one answer (the response). There is one desk, but many people can come and ask.

2

The rules of a service

📌 Properties of a service
  • A client/server system: one request, one response.
  • It can be synchronous (wait for the answer) or asynchronous (carry on and get a callback when it arrives).
  • Two message types: one for the request and one for the response, written in one .srv type separated by ---.
  • A service server exists only once, but it can have many clients.
3

Watch it

Animations: ROS 2 Documentation, "Understanding services", Open Robotics, CC BY 4.0.

4

Try it: never block while you wait

Call the adding machine below, then tick "blocking call" and call again: the client's timer stops. This is why every client you write today uses call_async.

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts


class AddTwoIntsServerNode(Node):
    def __init__(self):
        super().__init__("add_two_ints_server")
        self.server_ = self.create_service(
            AddTwoInts, "add_two_ints", self.callback_add_two_ints)
        self.get_logger().info("Add two ints server has been started")

    def callback_add_two_ints(self, request, response):
        response.sum = request.a + request.b
        self.get_logger().info(f"{request.a} + {request.b} = {response.sum}")
        return response


def main(args=None):
    rclpy.init(args=args)
    node = AddTwoIntsServerNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

The server callback receives the request and an empty response. You fill the response and return it. If you forget the return, the client never gets an answer.

📄 my_cpp_pkg/src/add_two_ints_server.cpp
#include "rclcpp/rclcpp.hpp"
#include "example_interfaces/srv/add_two_ints.hpp"

using std::placeholders::_1;
using std::placeholders::_2;

class AddTwoIntsServerNode : public rclcpp::Node
{
public:
    AddTwoIntsServerNode() : Node("add_two_ints_server")
    {
        server_ = this->create_service<example_interfaces::srv::AddTwoInts>(
            "add_two_ints", std::bind(&AddTwoIntsServerNode::callbackAddTwoInts, this, _1, _2));
        RCLCPP_INFO(this->get_logger(), "Service server has been started.");
    }

private:
    void callbackAddTwoInts(const example_interfaces::srv::AddTwoInts::Request::SharedPtr request,
                            const example_interfaces::srv::AddTwoInts::Response::SharedPtr response)
    {
        response->sum = request->a + request->b;
        RCLCPP_INFO(this->get_logger(), "%ld + %ld = %ld", request->a, request->b, response->sum);
    }
    rclcpp::Service<example_interfaces::srv::AddTwoInts>::SharedPtr server_;
};

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<AddTwoIntsServerNode>());
    rclcpp::shutdown();
    return 0;
}

CMakeLists: add_executable(add_two_ints_server src/add_two_ints_server.cpp), ament_target_dependencies(add_two_ints_server rclcpp example_interfaces) and add it to install(TARGETS …). The Python client works with the C++ server.

Ask the adding machine from code

Goal: a service client node that sends requests to /add_two_ints and prints each answer. Keep the server from Lab 2 running in another terminal.

1Write the service client (click the highlighted parts)
💻 Terminal
cd ~/ros2_ws/src/my_py_pkg/my_py_pkg
touch add_two_ints_client.py && chmod +x add_two_ints_client.py
📄 my_py_pkg/add_two_ints_client.py
#!/usr/bin/env python3
from functools import partial
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts


class AddTwoIntsClientNode(Node):
    def __init__(self):
        super().__init__("add_two_ints_client")
        self.client_ = self.create_client(AddTwoInts, "add_two_ints")
        while not self.client_.wait_for_service(1.0):
            self.get_logger().warn("Waiting for server add_two_ints...")
        self.send_request(3, 4)
        self.send_request(7, 4)
        self.send_request(5, 9)

    def send_request(self, a, b):
        request = AddTwoInts.Request()
        request.a = a
        request.b = b
        future = self.client_.call_async(request)
        future.add_done_callback(
            partial(self.callback_response, a=a, b=b))

    def callback_response(self, future, a, b):
        response = future.result()
        self.get_logger().info(f"{a} + {b} = {response.sum}")


def main(args=None):
    rclpy.init(args=args)
    node = AddTwoIntsClientNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

Three parts: create the client (same type and name as the server), send the request with call_async, and receive the answer in callback_response. add_done_callback only hands the callback the future; partial(f, a=a, b=b) adds a and b so each answer can be matched to its question. The node never stops and waits, so its timers and subscribers keep working.

🎮 GameYour service client, from start to answer: put the steps in order
  1. self.client_ = self.create_client(AddTwoInts, "add_two_ints")
  2. while not self.client_.wait_for_service(1.0): wait until the server is up
  3. self.send_request(3, 4): ask the first question
  4. request = AddTwoInts.Request(), then request.a = a and request.b = b
  5. future = self.client_.call_async(request)
  6. future.add_done_callback(partial(self.callback_response, a=a, b=b))
  7. rclpy.spin(node): the node keeps running while it waits
  8. The server adds the numbers and return response
  9. callback_response(future, a, b) logs 3 + 4 = 7

Solution: the new parts of number_counter.py
📄 my_py_pkg/number_counter.py
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from example_interfaces.msg import Int64
from example_interfaces.srv import SetBool


class NumberCounterNode(Node):
    def __init__(self):
        super().__init__("number_counter")
        self.counter_ = 0
        self.number_count_publisher_ = self.create_publisher(Int64, "number_count", 10)
        self.number_subscriber_ = self.create_subscription(
            Int64, "number", self.callback_number, 10)
        self.reset_counter_service_ = self.create_service(
            SetBool, "reset_counter", self.callback_reset_counter)
        self.get_logger().info("Number Counter has been started")

    def callback_number(self, msg):
        self.counter_ += msg.data
        new_msg = Int64()
        new_msg.data = self.counter_
        self.number_count_publisher_.publish(new_msg)

    def callback_reset_counter(self, request, response):
        if request.data:
            self.counter_ = 0
            response.success = True
            response.message = "Counter has been reset"
        else:
            response.success = False
            response.message = "Counter has not been reset"
        return response


def main(args=None):
    rclpy.init(args=args)
    node = NumberCounterNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()
Challenge 4.2 · Stretch · a preview of Lecture 7

The turtle army

Write a client node turtle_army.py that calls turtlesim's /spawn service 5 times to put turtles in a row at y = 2.0 and x = 1, 3, 5, 7, 9, named soldier1…soldier5. Log the name returned by each response. Add <depend>turtlesim</depend> to package.xml.

Solution
📄 my_py_pkg/turtle_army.py
#!/usr/bin/env python3
from functools import partial
import rclpy
from rclpy.node import Node
from turtlesim.srv import Spawn


class TurtleArmy(Node):
    def __init__(self):
        super().__init__("turtle_army")
        self.client_ = self.create_client(Spawn, "spawn")
        while not self.client_.wait_for_service(1.0):
            self.get_logger().warn("Waiting for turtlesim...")
        for i in range(5):
            self.spawn(f"soldier{i + 1}", 1.0 + 2.0 * i, 2.0)

    def spawn(self, name, x, y):
        request = Spawn.Request()
        request.x, request.y, request.theta, request.name = x, y, 1.57, name
        future = self.client_.call_async(request)
        future.add_done_callback(partial(self.on_spawned, name=name))

    def on_spawned(self, future, name):
        try:
            self.get_logger().info(f"{future.result().name} is alive")
        except Exception as e:
            self.get_logger().error(f"Could not spawn {name}: {e!r}")


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(TurtleArmy())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

4.3Actions, step by step

1Why2Picture it3How it works4Try it5How a goal ends6Remember it
1

Why services aren't enough

Services are perfect for quick questions. But imagine mission control asking a warehouse robot to "drive to shelf 12". It takes 30 seconds. With a service the client hears nothing for 30 s, can't tell whether the robot is stuck behind a box, and can't say "stop, I changed my mind". ROS 2 has a third way to talk for exactly this job: the action.

You saw it in the race in 4.0: only the action lane gets progress, can be cancelled, and reports when the robot is stuck.

2

Picture it: pizza with live tracking

🍕

An action is like ordering a pizza with live tracking. You place the order (the goal), the shop says "order accepted", the app keeps updating you ("in the oven", "on the way, 2 km") as feedback, and at the end you get the pizza (the result). If you change your mind you can cancel while it's still on the way. A service is phoning the shop to ask "are you open?": one question, one quick answer.

3

How it works: three services + two topics

An action is not new magic. ROS 2 builds every action from three services and two topics, hidden under the name <action>/_action/…. You will see them yourself in Lab 5.

Animation: ROS 2 Documentation, "Understanding actions", Open Robotics, CC BY 4.0.

4

Try it: turn the turtle, then cancel

5

How a goal ends

💡 The four endings of a goal
  • REJECTED: the server said no before starting (e.g. "shelf 99 doesn't exist").
  • SUCCEEDED: the job is done.
  • CANCELED: the client asked to stop and the server agreed.
  • ABORTED: the server gave up on its own (blocked, error, or a newer goal replaced it).
6

Remember it

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from turtlesim.action import RotateAbsolute


class TurtleRotateClientNode(Node):
    def __init__(self):
        super().__init__("turtle_rotate_client")
        self.client_ = ActionClient(self, RotateAbsolute, "turtle1/rotate_absolute")
        while not self.client_.wait_for_server(1.0):
            self.get_logger().warn("Waiting for action server...")
        self.send_goal(3.14)

    def send_goal(self, theta):
        goal = RotateAbsolute.Goal()
        goal.theta = theta
        future = self.client_.send_goal_async(goal, feedback_callback=self.callback_feedback)
        future.add_done_callback(self.callback_goal_response)

    def callback_goal_response(self, future):
        goal_handle = future.result()
        if not goal_handle.accepted:
            self.get_logger().warn("Goal rejected")
            return
        self.get_logger().info("Goal accepted")
        goal_handle.get_result_async().add_done_callback(self.callback_result)

    def callback_feedback(self, feedback_msg):
        remaining = feedback_msg.feedback.remaining
        self.get_logger().info(f"Remaining: {remaining:.2f} rad", throttle_duration_sec=0.5)

    def callback_result(self, future):
        result = future.result().result
        self.get_logger().info(f"Result: turned {result.delta:.2f} rad")


def main(args=None):
    rclpy.init(args=args)
    node = TurtleRotateClientNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

It is the service client with one extra idea. You create the client and send the goal the same way, and get three answers instead of one: goal accepted? (callback_goal_response), progress (callback_feedback, many times) and done (callback_result, once).

🎮 GameYour action client, from start to result: put the steps in order
  1. self.client_ = ActionClient(self, RotateAbsolute, "turtle1/rotate_absolute")
  2. while not self.client_.wait_for_server(1.0): wait until turtlesim is up
  3. self.send_goal(3.14): ask the turtle to face west
  4. goal = RotateAbsolute.Goal(), then goal.theta = theta
  5. future = self.client_.send_goal_async(goal, feedback_callback=self.callback_feedback)
  6. future.add_done_callback(self.callback_goal_response)
  7. callback_goal_response logs "Goal accepted" and calls get_result_async()
  8. callback_feedback logs "Remaining: … rad" while the turtle turns
  9. callback_result logs "Result: turned -3.14 rad"
➕ Going further (optional): write your own action server

You'll design your own .action files in Lecture 5. Until then, example_interfaces ships a ready-made one, Fibonacci: goal int32 order, result and feedback both int32[] sequence. This server computes one number per second, publishes the sequence so far as feedback, rejects silly goals, and honours cancel requests.

📄 my_py_pkg/fibonacci_server.py
#!/usr/bin/env python3
import time
import rclpy
from rclpy.node import Node
from rclpy.action import ActionServer, CancelResponse, GoalResponse
from rclpy.callback_groups import ReentrantCallbackGroup
from rclpy.executors import MultiThreadedExecutor
from example_interfaces.action import Fibonacci


class FibonacciServerNode(Node):
    def __init__(self):
        super().__init__("fibonacci_server")
        self.server_ = ActionServer(
            self, Fibonacci, "fibonacci",
            execute_callback=self.callback_execute,
            goal_callback=self.callback_goal,
            cancel_callback=self.callback_cancel,
            callback_group=ReentrantCallbackGroup())
        self.get_logger().info("Fibonacci action server has been started")

    def callback_goal(self, goal_request):
        if not 1 <= goal_request.order <= 40:              # say "no" before starting
            self.get_logger().warn(f"Rejecting goal: order = {goal_request.order}")
            return GoalResponse.REJECT
        return GoalResponse.ACCEPT

    def callback_cancel(self, goal_handle):
        self.get_logger().info("Cancel request received")
        return CancelResponse.ACCEPT                         # the default is REJECT!

    def callback_execute(self, goal_handle):
        feedback = Fibonacci.Feedback()
        feedback.sequence = [0, 1]
        for i in range(1, goal_handle.request.order):
            if goal_handle.is_cancel_requested:
                goal_handle.canceled()
                self.get_logger().info("Goal canceled")
                return Fibonacci.Result(sequence=feedback.sequence)
            feedback.sequence.append(feedback.sequence[i] + feedback.sequence[i - 1])
            goal_handle.publish_feedback(feedback)
            self.get_logger().info(f"Feedback: {list(feedback.sequence)}")
            time.sleep(1.0)                                  # pretend this is hard work
        goal_handle.succeed()
        return Fibonacci.Result(sequence=feedback.sequence)


def main(args=None):
    rclpy.init(args=args)
    node = FibonacciServerNode()
    rclpy.spin(node, executor=MultiThreadedExecutor())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

Now try {order: 0} (rejected) and {order: 20} stopped with Ctrl+C (canceled). Why the multi-threaded executor? callback_execute sleeps in a loop. With the default single-threaded executor nothing else can run meanwhile, so the cancel request would never be processed. The ReentrantCallbackGroup lets the cancel callback run in a second thread while the goal executes.

Challenge 4.3 · Stretch · actions

The compass dance

Write compass_dance.py: an action client that makes turtle1 face north, west, south, east (π/2, π, −π/2, 0), one after the other, logging each result. Send the next goal only when the previous one has SUCCEEDED; if any goal is canceled or aborted, stop the dance and log why. Test it by pressing F in teleop half-way.

Hint
Keep a list of headings and an index. In callback_result, on success, increase the index and call send_goal again. Do not send all four goals at once: turtlesim aborts the old goal when a new one arrives (you saw that in Lab 5).
Solution
📄 my_py_pkg/compass_dance.py
#!/usr/bin/env python3
import math
import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from action_msgs.msg import GoalStatus
from turtlesim.action import RotateAbsolute

HEADINGS = [("north", math.pi / 2), ("west", math.pi), ("south", -math.pi / 2), ("east", 0.0)]


class CompassDanceNode(Node):
    def __init__(self):
        super().__init__("compass_dance")
        self.client_ = ActionClient(self, RotateAbsolute, "turtle1/rotate_absolute")
        self.index_ = 0
        self.client_.wait_for_server()
        self.send_next()

    def send_next(self):
        name, theta = HEADINGS[self.index_]
        self.get_logger().info(f"Turning {name}")
        goal = RotateAbsolute.Goal()
        goal.theta = theta
        self.client_.send_goal_async(goal).add_done_callback(self.callback_goal_response)

    def callback_goal_response(self, future):
        goal_handle = future.result()
        if not goal_handle.accepted:
            self.get_logger().error("Goal rejected, the dance is over")
            return
        goal_handle.get_result_async().add_done_callback(self.callback_result)

    def callback_result(self, future):
        status = future.result().status
        name = HEADINGS[self.index_][0]
        if status != GoalStatus.STATUS_SUCCEEDED:
            reason = "canceled" if status == GoalStatus.STATUS_CANCELED else "aborted"
            self.get_logger().warn(f"Turn {name} was {reason}: stopping the dance")
            return
        self.get_logger().info(f"Facing {name} ✔")
        self.index_ += 1
        if self.index_ < len(HEADINGS):
            self.send_next()
        else:
            self.get_logger().info("Dance complete 🎉")


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(CompassDanceNode())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

✅ Knowledge checkLecture 4 check: 8 questions

How many servers can offer /add_two_ints at once?

A service name has exactly one server; any number of clients can call it.

What must the server callback end with?

If the response is not returned, the client never gets an answer.

Why use call_async + add_done_callback inside a node?

Blocking inside a callback freezes the whole node, as you saw in the simulator.

The client prints "Waiting for server…" forever. Most likely cause?

Check ros2 service list for the exact name.

What does an action have that a service doesn't?

Goal → feedback… → result, cancellable at any time.

In a .action file, what is the order of the three parts?

Goal --- result --- feedback. In RotateAbsolute: theta, delta, remaining.

You press an arrow key while turtlesim is rotating to a goal. How does the goal end?

Cancel comes from the client (the F key). A velocity command makes the server abort on its own.

Under the hood, an action is built from…

send_goal, cancel_goal, get_result services + feedback, status topics. You listed them in Lab 5.
