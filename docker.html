Docker Demo — ROS 2 Humble in Your Browser

Nobody likes install sessions. So today the install is the lesson: you install Docker, pull a ready-made ROS 2 desktop, open it in your browser at localhost:6080, and then learn to shut it down and bring it back without losing your work. If you already know Docker, this takes 5 minutes. If you don't, you leave with a skill every robotics engineer uses.
⏱ ~45 min (most of it is the download)
🐧 Ubuntu 22.04 · ROS 2 Humble · noVNC desktop
💻 Windows · macOS · Linux

🎯 By the end of this demo you can…

  • Explain the difference between an image and a container.
  • Install Docker and fix the "virtualization not detected" error on Windows.
  • Pull an image and run it as a container with ports, a network and a name.
  • Open a full ROS 2 Ubuntu desktop at http://localhost:6080 and run a ROS 2 demo.
  • Stop, start, list and delete containers and images at will.

D.0The idea in 5 minutes

🍰

An image is a recipe; a container is the cake. The image (thinkautonomous/ros2-humble-ubuntu-desktop-vnc) is a read-only snapshot of Ubuntu 22.04 with ROS 2 Humble and a desktop already installed. When you run it, Docker bakes a container from it: a live, isolated machine you can work in. You can bake many cakes from one recipe, and eating one cake doesn't change the recipe.

If you've written Python classes: an image is like a class, and a container is like an object made from it.

📌 Why roboticists love Docker
  • Same environment for everyone: Windows, Mac and Linux students all get the identical Ubuntu 22.04 + ROS 2 Humble.
  • Nothing to break: mess it up? Delete the container and run a fresh one in seconds.
  • Real-world skill: robots in industry ship their software as Docker images. The LIMO, Nav2 CI, and most ROS 2 research code all use them.

L0Lab 0 — Install Docker

LAB 0 · 10–20 min

Get Docker running on your computer

Goal: docker run hello-world prints "Hello from Docker!".

1Install Docker for your OS
OSWhat to install
🪟 Windows 10/11Docker Desktop from docker.com. During setup keep "Use WSL 2 instead of Hyper-V" ticked. Restart when asked.
🍎 macOSDocker Desktop from docker.com (pick Apple Silicon or Intel).
🐧 LinuxEither Docker Desktop or Docker Engine (commands below).
🐧 Linux terminal (Docker Engine, Ubuntu)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER     # run docker without sudo (log out and back in)
sudo systemctl start docker
💡 Docker must be running before every session

Always open the Docker Desktop app first (Windows/Mac), or run sudo systemctl start docker (Linux). Otherwise every docker command fails with "Cannot connect to the Docker daemon".

2Check Docker works
💻 Terminal (PowerShell / Command Prompt / bash)
docker --version
docker run hello-world
✅ You should see
Docker version 2x.x.x, build ...
...
Hello from Docker!
This message shows that your installation appears to be working correctly.

Did it work? Skip to Lab 1. On Windows, if Docker Desktop says "Virtualization support not detected" or the engine won't start, do step 3.

3🪟 Windows only: fix "virtualization not detected"

Docker Desktop on Windows needs hardware virtualization, plus WSL 2 (or Hyper-V). One of these layers is off. Check them in this order:

3a. Is virtualization enabled in the firmware? Open Task Manager → Performance → CPU and look at Virtualization at the bottom right.

  • Disabled → reboot into BIOS/UEFI (usually F2, F10, Del or Esc at boot). Enable Intel VT-x / Virtualization Technology, or SVM Mode on AMD. Save and reboot.
  • Enabled → go on to 3b.

3b. Enable the Windows features Docker needs. Open PowerShell as Administrator:

🛡️ PowerShell (Administrator)
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
wsl --install --no-distribution
wsl --update
wsl --set-default-version 2

On Windows Pro/Enterprise you can also enable the Hyper-V backend (optional):

🛡️ PowerShell (Administrator) · optional
dism.exe /online /enable-feature /featurename:Microsoft-Hyper-V /all

3c. Make sure the hypervisor launches at boot. Other VM tools sometimes switch this off:

🛡️ PowerShell (Administrator)
bcdedit /set hypervisorlaunchtype auto
⚠️ Restart the whole PC

After 3b and 3c you need a full Windows restart, not just a Docker restart.

3d. Verify, then start Docker.

💻 PowerShell
wsl --status
systeminfo | findstr /i "hypervisor"
✅ The second command should report
A hypervisor has been detected. Features required for Hyper-V will not be displayed.

Now launch Docker Desktop. In Settings → General, make sure "Use the WSL 2 based engine" is ticked.

📌 Common gotchas
  • Windows inside a VM (VMware, Proxmox, a cloud VM): nested virtualization must be enabled on the host. For a Hyper-V host: Set-VMProcessor -VMName <name> -ExposeVirtualizationExtensions $true.
  • Old VirtualBox or VMware versions can conflict with Hyper-V/WSL 2. Update them to current releases.
  • University or managed lab machines may have virtualization locked in BIOS by IT. Ask IT, or use your own laptop.

L1Lab 1 — Pull & run your first ROS 2 container

LAB 1 · 10 min + download

From Docker Hub to a running ROS 2 desktop

Goal: a container called ros2_container is running and its log shows novnc and vnc in the RUNNING state.

1Pull the image (optional but clearer)

docker run pulls the image automatically if it's missing, but pulling first separates "download" from "create", so you can see each step. The image is a few GB, so this is the slow part. Use a good connection.

💻 Terminal
docker pull thinkautonomous/ros2-humble-ubuntu-desktop-vnc
docker images
✅ You should see (layer IDs will differ)
latest: Pulling from thinkautonomous/ros2-humble-ubuntu-desktop-vnc
4f4fb700ef54: Pull complete
5b75391628c6: Pull complete
...
Digest: sha256:4606816540dc...
Status: Downloaded newer image for thinkautonomous/ros2-humble-ubuntu-desktop-vnc:latest

REPOSITORY                                       TAG      IMAGE ID   SIZE
thinkautonomous/ros2-humble-ubuntu-desktop-vnc   latest   ...        ...GB

Each line is a layer. An image is a stack of layers (Ubuntu, then ROS, then the desktop…). Layers that other images share are downloaded only once.

2Create the network (once, ever)

Our run command attaches the container to a network called ros_network. Docker doesn't create it for you, so if you skip this step you get network ros_network not found.

💻 Terminal
docker network create ros_network
docker network ls
✅ You should see
NETWORK ID     NAME          DRIVER    SCOPE
...            bridge        bridge    local
...            host          host      local
...            ros_network   bridge    local

The network stays across reboots. Any other container you put on ros_network (e.g. a second ROS 2 container, see Lab 5) can reach this one by its container name.

3Run it: the one important line
💻 Terminal
docker run -p 6080:80 --shm-size=512m --security-opt seccomp=unconfined --network ros_network --name ros2_container thinkautonomous/ros2-humble-ubuntu-desktop-vnc

Let's break it down, piece by piece:

PieceWhat it does
docker runCreates a new container from an image and starts it. Pulls the image first if it isn't on your disk.
-p 6080:80Port mapping HOST:CONTAINER. The desktop's web server listens on port 80 inside the container; you reach it on port 6080 of your PC.
--shm-size=512mGives the container 512 MB of shared memory. The desktop, RViz and Gazebo need more than Docker's default 64 MB, or they crash or show a blank screen.
--security-opt seccomp=unconfinedRelaxes a security filter. Required for Ubuntu 22.04 (Jammy) desktop images like this one, as the container log itself reminds you.
--network ros_networkJoins the network you created in step 2.
--name ros2_containerA human-friendly name, so you can type docker stop ros2_container instead of a long ID.
thinkautonomous/ros2-humble-ubuntu-desktop-vncThe image: account/repository on Docker Hub. No tag means :latest.
✅ The container log ends with
* enable custom user: ubuntu
useradd: warning: the home directory /home/ubuntu already exists.
useradd: Not copying any file from skel directory into it.
grep: /home/ubuntu/.bashrc: No such file or directory
============================================================================
NOTE: --security-opt seccomp=unconfined flag is required to launch Ubuntu Jammy based image.
============================================================================
... INFO supervisord started with pid 46
... INFO spawned: 'novnc' with pid 47
... INFO spawned: 'vnc' with pid 48
... INFO success: novnc entered RUNNING state, process has stayed up for > than 1 seconds (startsecs)
... INFO success: vnc entered RUNNING state, process has stayed up for > than 1 seconds (startsecs)
💡 Read the log like an engineer

The useradd and .bashrc warnings at the top are normal for this image and can be ignored. The two lines that matter are the last ones: novnc and vnc entered RUNNING state. That means the desktop is up.

⚠️ Leave this terminal open

The container is attached to this window. Closing it or pressing Ctrl+C stops the container. To get your terminal back, add -d (detached) to the run command: docker run -d -p 6080:80 .... Then watch the log with docker logs -f ros2_container.

L2Lab 2 — Open ROS 2 in your browser

LAB 2 · 5 min

Ubuntu + ROS 2 in a browser tab

Goal: the talker and listener demo nodes are chatting inside the container's desktop.

1Open the desktop

In Chrome, Edge, Firefox or Safari, go to:

🌐 Browser address bar
http://localhost:6080
  • If you see a file list instead of a desktop, click vnc.html (or go straight to http://localhost:6080/vnc.html), then click Connect.
  • It's http, not https. With https:// the page won't load.
  • localhost and 127.0.0.1 mean the same thing: your own computer.
🔑 VNC password

When the browser asks for the password, type: tarosbox

For sudo or a login prompt inside the desktop, the default user is ubuntu with password ubuntu (the default in the Tiryoh-based images this one builds on).

✅ You should see
An Ubuntu (LXDE) desktop inside the browser tab, with a menu and a terminal icon.
2Check ROS 2 is there

Open a terminal inside the browser desktop (menu → System Tools → Terminal, or the terminal icon).

🖥️ Desktop terminal 1
source /opt/ros/humble/setup.bash
printenv ROS_DISTRO
ros2 run demo_nodes_cpp talker
✅ You should see
humble
[INFO] [talker]: Publishing: 'Hello World: 1'
[INFO] [talker]: Publishing: 'Hello World: 2'
...
3Listen, and see the graph

Open a second terminal in the desktop:

🖥️ Desktop terminal 2
source /opt/ros/humble/setup.bash
ros2 run demo_nodes_py listener
✅ You should see
[INFO] [listener]: I heard: [Hello World: 7]
[INFO] [listener]: I heard: [Hello World: 8]

Now open a third terminal and try ros2 node list, ros2 topic list and rqt_graph. Everything you learn in the lectures works here.

4Bonus: a GUI demo
🖥️ Desktop terminals
ros2 run turtlesim turtlesim_node
ros2 run turtlesim turtle_teleop_key

A turtle window opens inside the browser desktop. Click the teleop terminal and drive with the arrow keys. If turtlesim isn't in the image, install it once: sudo apt update && sudo apt install -y ros-humble-turtlesim. It stays installed in this container.

💡 Save typing

Run echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc once. Every new desktop terminal then has ROS 2 ready.

L3Lab 3 — Shut it down!

🛑

"But I just got there! I'm not going to shut it down!" Well, you'll work a few hours in your box, and tonight you'll want to close it. Tomorrow you'll want it back with all your work. That isn't trivial if you don't know the commands, so let's practise now.

LAB 3 · 5 min

Stop the container without losing it

Goal: docker ps is empty, but docker ps -a still shows ros2_container.

1List running containers

Open a new terminal on your own computer (not inside the browser desktop):

💻 Host terminal
docker ps
✅ You should see
CONTAINER ID   IMAGE                                            ...   STATUS         PORTS                  NAMES
8bd72ec838b1   thinkautonomous/ros2-humble-ubuntu-desktop-vnc   ...   Up 12 minutes  0.0.0.0:6080->80/tcp   ros2_container
2Stop it
💻 Host terminal
docker stop ros2_container      # or: docker stop 8bd72ec838b1  (the ID, or just its first few characters)
docker ps

The browser tab disconnects and docker ps is now empty. Don't worry: the container still exists, on your disk and in your heart. ❤️

3Prove it still exists
💻 Host terminal
docker ps -a
✅ You should see
CONTAINER ID   IMAGE                                            ...   STATUS                     NAMES
8bd72ec838b1   thinkautonomous/ros2-humble-ubuntu-desktop-vnc   ...   Exited (0) 5 seconds ago   ros2_container

-a means all: running and stopped. Keep this in mind, because it explains the most common error in the next lab.

L4Lab 4 — Start & stop containers at will

LAB 4 · 10 min

run once, start forever

Goal: bring ros2_container back with one short command and find your work still there.

1Try the wrong way first (on purpose)

Run the exact same docker run line from Lab 1 again:

💻 Host terminal
docker run -p 6080:80 --shm-size=512m --security-opt seccomp=unconfined --network ros_network --name ros2_container thinkautonomous/ros2-humble-ubuntu-desktop-vnc
❌ You get
docker: Error response from daemon: Conflict. The container name "/ros2_container" is already in use by container "8bd72ec838b1...". You have to remove (or rename) that container to be able to reuse that name.

That's correct behaviour. docker run means create, and you asked Docker to create a container that already exists. You have two options.

2✅ Option A (the one you want): start the existing container
💻 Host terminal
docker ps -a                    # note the NAME or ID
docker start ros2_container     # or: docker start 8bd72ec838b1

docker start brings the container back in exactly the configuration it was created with (same ports, network, shm size), so you don't need any parameters. It also keeps everything you installed or built inside it.

Refresh http://localhost:6080. Your desktop is back. ✨ So the magic command is docker start.

💡 Detached by default

docker start runs in the background and gives your terminal back straight away. To watch the log, use docker logs -f ros2_container (Ctrl+C only stops watching here, not the container). To attach to it instead, use docker start -a ros2_container.

3Option B: create a second, separate container

Same command, different --name, and a different host port, because 6080 is already taken while the first one runs:

💻 Host terminal
docker run -d -p 6081:80 --shm-size=512m --security-opt seccomp=unconfined --network ros_network --name ros2_container2 thinkautonomous/ros2-humble-ubuntu-desktop-vnc

Open http://localhost:6081: a brand-new, clean desktop. Nothing from the first container is in it, and the image was not downloaded again. One recipe, two cakes. 🍰🍰

4Clean up what you don't need
💻 Host terminal
docker stop ros2_container2
docker rm ros2_container2       # delete the container (its files are gone!)
docker ps -a                    # only ros2_container left
⚠️ docker rm is permanent

docker rm deletes the container and everything you did inside it. docker rmi deletes the image (you'd have to download it again). Keep your real code in Git, or in a mounted folder (Lab 5).

🧠 Daily routine (memorise this)
  1. Open Docker Desktop (or sudo systemctl start docker).
  2. docker start ros2_container
  3. Browse to http://localhost:6080, enter the VNC password tarosbox, and work.
  4. docker stop ros2_container when you're done.

It really is a one-click solution: an experienced Docker user just runs the image and opens the browser. We took the long way so that you now have real Docker skills.

L5Lab 5 — Bonus demos 🐳

LAB 5 · optional · 20 min

Things real robotics teams do with Docker

Goal: control the container from your own terminal, share files with it, and make two containers talk ROS 2.

1Get a shell inside the running container from your own terminal
💻 Host terminal
docker exec -it ros2_container bash
🐳 Now you're inside the container
source /opt/ros/humble/setup.bash
ros2 topic list
exit                            # leaves the shell; the container keeps running

exec runs a command in a container that is already running. -it = interactive + terminal. This is the fastest way to work if you don't need the desktop.

2Copy files in and out
💻 Host terminal
docker cp my_node.py ros2_container:/home/ubuntu/        # host → container
docker cp ros2_container:/home/ubuntu/map.yaml .          # container → host
3Share a workspace folder (a volume mount)

A mounted folder lives on your disk, so your code survives even docker rm, and you can edit it in VS Code on your host. Mounts are set when a container is created, so this makes a new container:

💻 Host terminal (Windows: use a path like C:\Users\you\ros2_ws)
docker run -d -p 6082:80 --shm-size=512m --security-opt seccomp=unconfined --network ros_network -v ~/ros2_ws:/home/ubuntu/ros2_ws --name ros2_dev thinkautonomous/ros2-humble-ubuntu-desktop-vnc

-v HOST_PATH:CONTAINER_PATH. Open http://localhost:6082. Anything in /home/ubuntu/ros2_ws is the same folder as ~/ros2_ws on your PC.

4Two containers, one ROS 2 graph

This is why we created ros_network. Start a talker in a separate container (the official osrf/ros:humble-desktop image, a large download), and listen to it from your desktop container:

💻 Host terminal
docker run -it --rm --network ros_network --name ros2_talker osrf/ros:humble-desktop ros2 run demo_nodes_cpp talker
🖥️ Terminal in the browser desktop (ros2_container)
source /opt/ros/humble/setup.bash
ros2 run demo_nodes_py listener

Two "computers", one ROS 2 graph. ROS 2 discovery finds nodes across containers on the same Docker network, just like across robots on the same Wi-Fi. --rm deletes the talker container automatically when you press Ctrl+C. If the listener hears nothing, check that both containers use the same ROS_DOMAIN_ID (default 0).

D.1When things go wrong

You see…WhyFix
Virtualization support not detected / Docker engine won't start (Windows)Virtualization off in BIOS, WSL 2 missing, or hypervisor disabled at boot.Follow Lab 0, step 3, then do a full restart.
Cannot connect to the Docker daemon / error during connectDocker isn't running.Open Docker Desktop, or run sudo systemctl start docker.
network ros_network not foundThe network was never created.docker network create ros_network (once), then run again.
Conflict. The container name "/ros2_container" is already in useThe container already exists (maybe stopped, or left over from a failed run). docker ps doesn't show stopped ones.Use docker start ros2_container. If it came from a failed attempt, docker rm ros2_container, then docker run again.
port is already allocatedAnother container or app already uses host port 6080.Stop the other container, or map another port: -p 6081:80 → http://localhost:6081.
Browser: "This site can't be reached" / connection resetWrong URL (https), wrong port, or the container isn't running.Use http://localhost:6080. Check docker ps shows 0.0.0.0:6080->80/tcp. On Docker Desktop, set the host port to 6080 → container 80 (not 8080:8080).
Desktop is black/grey, or RViz/Gazebo crashToo little shared memory.Make sure the container was created with --shm-size=512m (or larger, e.g. 1g). This needs a new container.
Container exits right awayMissing --security-opt seccomp=unconfined on a Jammy image.docker logs ros2_container to read why, then docker rm and re-run with the full command.
Desktop disappeared when I closed the terminalThe container was attached to that window; closing it or Ctrl+C stops it.docker start ros2_container. Next time use -d with docker run.
Want a desktop VNC app (Remmina, VNC Viewer) instead of the browserThe browser route uses port 80 only.The browser is the supported route. For a native client you must also publish the VNC port when creating the container (e.g. -p 5900:5900) and connect to 127.0.0.1:5900.
Running out of disk spaceOld images and stopped containers pile up.docker ps -a → docker rm; docker images → docker rmi; or docker system prune (removes all stopped containers, so be careful!).

D.2Exit ticket (5 min)

You stopped your container last night. What single command brings it back this morning?

Answer
docker start ros2_container, not docker run.

Why does running the same docker run ... --name ros2_container ... twice fail?

Answer
docker run creates a container, and a container with that name already exists (even if stopped) → name conflict.

In -p 6080:80, which number is on your PC and which is inside the container?

Answer
6080 is the host (your PC, in the browser URL); 80 is inside the container. Format: HOST:CONTAINER.

docker ps is empty, but you're sure you created a container. How do you see it?

Answer
docker ps -a lists stopped containers too.

What's the difference between docker rm and docker rmi?

Answer
rm deletes a container (and your work inside it); rmi deletes an image (you'd have to pull it again).
