0.1Why this comes first

ROS 2 is not an app you click. It is a set of programs that talk to each other, and you start, inspect and debug them from a Linux terminal. On the real LIMO you will often have no screen at all, only an SSH session over Wi-Fi. Students who struggle in robotics courses rarely struggle with the robotics. They struggle because source, chmod +x, ROS_DOMAIN_ID or a missing colcon build stands between them and a moving robot.

Work through the toolkit in this order. Each step is what the next one depends on:

STEP 1
Navigate & manage filespwd, ls, cd, mkdir -p, cp, mv, rm: you will live inside ~/limo_ws.
STEP 2
Read, search & pipecat, less, grep, find, |: turn a wall of log output into the one line you need.
STEP 3
Permissions & processeschmod +x, sudo, the dialout group, Ctrl+C, kill: run nodes and stop the stuck ones.
STEP 4
Environment variablessource, export, ~/.bashrc: this is how ROS 2 finds its packages, and yours.
STEP 5
The ROS 2 CLIros2 <verb> <sub-verb>: nodes, topics, services, actions, params, launch, bags, TF.

Users, permissions & ownership

🤖 Robotics note

0.5Environment & ~/.bashrc

ROS 2 is configured almost entirely through environment variables. source /opt/ros/humble/setup.bash doesn't install or start anything. It sets variables such as PATH, AMENT_PREFIX_PATH and ROS_DISTRO in the current terminal only, so the ros2 command can find its packages. Open a new terminal and those variables are gone. That is the cause of most "package not found" mysteries.

CommandWhat it doesExample
echo $VARPrint a variableecho $ROS_DISTRO
export VAR=valueSet a variable for this terminalexport ROS_DOMAIN_ID=7
printenv | grep ROSCheck which ROS variables are setprintenv | grep ROS
source <file>Run a file inside the current shellsource ~/limo_ws/install/setup.bash
aliasCreate a shortcutalias cb='colcon build --symlink-install'

Add this block to the end of ~/.bashrc (nano ~/.bashrc). It runs in every new terminal, so you only set things up once:

# ---- ROS 2 setup (ROS and Robot Programming) ----
source /opt/ros/humble/setup.bash                # use jazzy on Ubuntu 24.04
[ -f ~/limo_ws/install/setup.bash ] && source ~/limo_ws/install/setup.bash
export ROS_DOMAIN_ID=7                            # pick a unique number per team (0-101)
source /usr/share/colcon_argcomplete/hook/colcon-argcomplete.bash
alias cb='cd ~/limo_ws && colcon build --symlink-install'
alias sws='source ~/limo_ws/install/setup.bash'
📌 Why ROS_DOMAIN_ID matters in a lab

Every ROS 2 computer on the same Wi-Fi and the same domain ID sees every other computer's topics. With 30 students on domain 0, your teleop can drive someone else's robot. Pick a unique number per team and keep it in ~/.bashrc. On ROS 2 Humble, export ROS_LOCALHOST_ONLY=1 keeps traffic on your own machine entirely. Jazzy replaces it with ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST.

0.7ROS 2 in one page

A ROS 2 robot is a team of small programs called nodes. Each does one job: a camera driver, a planner, a motor controller. They talk through three kinds of connection, and picking the right one is the first design decision in every ROS 2 program you'll write.

ConceptWhat it isUse it when…LIMO example
NodeOne program doing one jobAlways. Every piece of the robot is one/limo_base
TopicContinuous many-to-many stream (publish/subscribe)Data flows all the time: sensors, velocity commands/scan, /cmd_vel, /odom
ServiceRequest → response, quick and one-offYou want an answer now: reset, spawn, save a map/reset
ActionLong-running goal with feedback and cancelThe task takes seconds or minutes and might be cancelled/navigate_to_pose
ParameterA configurable value owned by a nodeTuning without recompilingmax_speed: 0.5
InterfaceThe message, service or action type definitionDeciding what data looks likegeometry_msgs/msg/Twist
Launch fileStarts and configures many nodes at onceMore than one node (always, in practice)limo_gazebo_diff.launch.py
WorkspaceA folder where you build your own packagesWriting any code of your own~/limo_ws
DDS / Domain IDThe middleware. Nodes only see each other on the same domainSeveral robots or teams share one networkROS_DOMAIN_ID=7
🧭 The one pattern to remember

Every command follows ros2 <verb> <sub-verb> [args]. Type ros2 and press Tab twice to see all verbs. ros2 topic -h lists the topic sub-verbs. If you are unsure, add -h.

0.9Anatomy of a ROS 2 package

Every package you write or clone has the same skeleton. Knowing which file does what tells you where to look when a build fails.

File / folderPython package (ament_python)C++ package (ament_cmake)
package.xmlName, version, maintainer and dependencies. rosdep reads this
Build instructionssetup.py + setup.cfgCMakeLists.txt
Source codepackage_name/*.pysrc/*.cpp + include/package_name/*.hpp
Other folderslaunch/, config/, urdf/. Custom msg/, srv/, action/ definitions go in a CMake package

Python: register nodes and install launch files in setup.py

import os
from glob import glob
from setuptools import find_packages, setup

package_name = 'my_pkg'

setup(
    name=package_name,
    packages=find_packages(exclude=['test']),
    data_files=[
        ('share/ament_index/resource_index/packages', ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        # without these two lines, 'ros2 launch' can't find your launch/config files
        (os.path.join('share', package_name, 'launch'), glob('launch/*.launch.py')),
        (os.path.join('share', package_name, 'config'), glob('config/*.yaml')),
    ],
    install_requires=['setuptools'],
    entry_points={
        'console_scripts': [
            # executable name = module:function  →  ros2 run my_pkg my_node
            'my_node = my_pkg.my_node:main',
        ],
    },
)

C++: the CMakeLists.txt essentials

cmake_minimum_required(VERSION 3.8)
project(my_cpp_pkg)
find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)

add_executable(my_node src/my_node.cpp)
ament_target_dependencies(my_node rclcpp)

install(TARGETS my_node DESTINATION lib/${PROJECT_NAME})
install(DIRECTORY launch config DESTINATION share/${PROJECT_NAME})

ament_package()

0.10Troubleshooting checklist

Before you ask for help, run ros2 node list, ros2 topic list -t, ros2 topic info -v and rqt_graph, and read the full error message. Most problems are in this table:

SymptomLikely causeFix / check
Package not foundWorkspace not built or not sourcedcolcon build && source install/setup.bash
No executable foundMissing entry_points in setup.py, or install() in CMakeLists.txtros2 pkg executables my_pkg
Topic listed, but echo prints nothingQoS mismatch (sensor data is often BEST_EFFORT)ros2 topic info /scan -v
Nodes can't see each otherDifferent ROS_DOMAIN_ID, a firewall, or different networksecho $ROS_DOMAIN_ID ; ros2 multicast receive
Other people's topics show up on your machineShared Wi-Fi and the same domainexport ROS_DOMAIN_ID=23
TF "extrapolation" errorsClock mismatch or a missing use_sim_time--ros-args -p use_sim_time:=true
Build freezes the VM or PiOut of RAM from parallel compilingcolcon build --parallel-workers 1
Serial device: permission deniedUser not in the dialout groupsudo usermod -aG dialout $USER
Stale nodes or topics listed after a crashThe discovery daemon cached old entriesros2 daemon stop && ros2 daemon start
Gazebo won't reopen ("address in use")A leftover gzserver is still runningpkill -f gzserver ; pkill -f gzclient

B9Run a second turtlesim in the namespace /robot2 and drive it with teleop through remapping.

Solution
ros2 run turtlesim turtlesim_node --ros-args -r __ns:=/robot2
ros2 run turtlesim turtle_teleop_key --ros-args -r /turtle1/cmd_vel:=/robot2/turtle1/cmd_vel

B10Record 20 s of /turtle1/cmd_vel while driving, reset the sim, and replay the bag at 2× speed.

Solution
ros2 bag record -o turtle_run /turtle1/cmd_vel   # drive ~20 s, then Ctrl+C
ros2 service call /reset std_srvs/srv/Empty
ros2 bag play turtle_run -r 2.0

B11Create a Python package lab_b with a launch file that starts both turtlesims from B9. Build it, source it and launch it.

Solution outline
cd ~/ros2_ws/src
ros2 pkg create lab_b --build-type ament_python --dependencies rclpy
mkdir -p lab_b/launch     # write two_sims.launch.py (see 0.9) with namespace='robot2' on the 2nd Node
# add the launch/ line to data_files in setup.py (see 0.9), then:
cd ~/ros2_ws && colcon build --packages-select lab_b
source install/setup.bash
ros2 launch lab_b two_sims.launch.py

Solution
