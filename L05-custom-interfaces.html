Check yourself 5 min

The car's camera sends images. Do you write a custom message for them?

Answer
No. sensor_msgs/msg/Image already exists, and every tool (RViz, rqt, OpenCV bridges) understands it. Reuse before you create.

In the "scribbled note" simulator, why did the planner crash when the teammate changed the order?

Answer
A String has no named fields, so the planner guessed "the 3rd item is the distance". With a custom message, msg.distance_m is always the distance, whatever order it was filled in.

The perception node sends DetectedObject; the planner subscribes with String. What happens?

Answer
Nothing arrives, with no error in either node. A topic connects only publishers and subscribers of the same type. ros2 topic info would show two types on one topic.

The same planner runs in a city (max 50 km/h) and on a motorway (max 110 km/h). Two programs?

Answer
No: one program with a parameter max_speed, started with a different value (or YAML file) in each place.

"Park in bay 7, tell me the distance left, let me cancel." Which file would you write?

Answer
A .action: goal (bay number) --- result --- feedback (distance left). Same shape as RotateAbsolute from Lecture 4.

5.1Custom interfaces, step by step

1Picture it2The rules3Watch it4Try it5Remember it
1

Picture it: a printed form, not a scribbled note

📝

An interface is a printed form with labelled boxes. The topic is the post box; the interface is the form you post. Everyone agrees that the box called distance_m holds a decimal number in metres. A scribbled note ("car 0.92 12.5") might be understood today, and misread tomorrow.

2

The rules of an interface

📌 Name + type, every time
  • A topic is identified by a name (/hardware_status) and a type (my_robot_interfaces/msg/HardwareStatus). A service and an action too. Both sides must use the same type.
  • Topics, services and actions are the communication layer; interfaces are the content.
  • One field per line: type name. Comments start with #.
  • Interfaces live in their own package (here my_robot_interfaces), which must be a CMake package, so both Python and C++ packages can use them.

Field types you can use

⚠️ Naming rules (the build fails if you break them)
  • File names: CamelCase, starting with a capital, no underscores: HardwareStatus.msg ✔ hardware_status.msg ✘
  • Field names: snake_case, lower case, starting with a letter: are_motors_ready ✔ AreMotorsReady ✘ _speed ✘
  • Constants: UPPER_CASE with a value: uint8 PEDESTRIAN=1
3

Watch it: from a text file to code in every language

You write a few lines of text. colcon build runs the rosidl code generators, which write a Python class, a C++ struct and the network description for you. That is why a Python node and a C++ node can exchange your message without any extra work.

4

Pick a preset (the three marked car are today's self-driving examples), add or rename fields, and watch the file, the CMakeLists.txt line and the Python code update. Break a naming rule on purpose and read the warning.

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from my_robot_interfaces.msg import HardwareStatus


class HardwareStatusPublisherNode(Node):
    def __init__(self):
        super().__init__("hardware_status_publisher")
        self.hw_status_publisher_ = self.create_publisher(
            HardwareStatus, "hardware_status", 10)
        self.timer_ = self.create_timer(1.0, self.publish_hw_status)
        self.get_logger().info("Hardware status publisher has been started")

    def publish_hw_status(self):
        msg = HardwareStatus()
        msg.temperature = 45
        msg.are_motors_ready = True
        msg.debug_message = "Nothing special here"
        self.hw_status_publisher_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = HardwareStatusPublisherNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from my_robot_interfaces.srv import SetDrivingMode

MODES = ["manual", "eco", "sport", "autopilot"]


class DrivingModeServerNode(Node):
    def __init__(self):
        super().__init__("driving_mode_server")
        self.mode_ = "manual"
        self.server_ = self.create_service(
            SetDrivingMode, "set_driving_mode", self.callback_set_driving_mode)
        self.get_logger().info("Driving mode server started in mode: manual")

    def callback_set_driving_mode(self, request, response):
        if request.mode not in MODES:
            response.success = False
            response.message = f"Unknown mode '{request.mode}'. Use one of {MODES}"
            return response
        self.mode_ = request.mode
        response.success = True
        response.message = f"Driving mode is now {self.mode_}"
        self.get_logger().info(response.message)
        return response


def main(args=None):
    rclpy.init(args=args)
    node = DrivingModeServerNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

➕ Going further (optional): the DriveDistance action server

The Fibonacci server from Lecture 4, with your own type. It "drives" in half-second steps, publishes the distance left as feedback, rejects silly goals and accepts cancel requests.

📄 my_py_pkg/drive_distance_server.py
#!/usr/bin/env python3
import time
import rclpy
from rclpy.node import Node
from rclpy.action import ActionServer, CancelResponse, GoalResponse
from rclpy.callback_groups import ReentrantCallbackGroup
from rclpy.executors import MultiThreadedExecutor
from my_robot_interfaces.action import DriveDistance


class DriveDistanceServerNode(Node):
    def __init__(self):
        super().__init__("drive_distance_server")
        self.server_ = ActionServer(
            self, DriveDistance, "drive_distance",
            execute_callback=self.callback_execute,
            goal_callback=self.callback_goal,
            cancel_callback=self.callback_cancel,
            callback_group=ReentrantCallbackGroup())
        self.get_logger().info("Drive distance action server has been started")

    def callback_goal(self, goal_request):
        if goal_request.distance_m <= 0.0 or goal_request.speed_mps <= 0.0:
            self.get_logger().warn("Rejecting goal: distance and speed must be > 0")
            return GoalResponse.REJECT
        return GoalResponse.ACCEPT

    def callback_cancel(self, goal_handle):
        return CancelResponse.ACCEPT

    def callback_execute(self, goal_handle):
        goal = goal_handle.request
        feedback = DriveDistance.Feedback()
        travelled = 0.0
        step = goal.speed_mps * 0.5                     # metres covered every 0.5 s
        while travelled < goal.distance_m:
            if goal_handle.is_cancel_requested:
                goal_handle.canceled()
                return DriveDistance.Result(travelled_m=travelled)
            travelled = min(goal.distance_m, travelled + step)
            feedback.remaining_m = goal.distance_m - travelled
            goal_handle.publish_feedback(feedback)
            time.sleep(0.5)
        goal_handle.succeed()
        return DriveDistance.Result(travelled_m=travelled)


def main(args=None):
    rclpy.init(args=args)
    node = DriveDistanceServerNode()
    rclpy.spin(node, executor=MultiThreadedExecutor())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from my_robot_interfaces.msg import LedStateArray
from my_robot_interfaces.srv import SetLed


class LedPanelNode(Node):
    def __init__(self):
        super().__init__("led_panel")
        self.led_states_ = [0, 0, 0]
        self.led_states_publisher_ = self.create_publisher(LedStateArray, "led_states", 10)
        self.led_states_timer_ = self.create_timer(4.0, self.publish_led_states)
        self.set_led_service_ = self.create_service(SetLed, "set_led", self.callback_set_led)
        self.get_logger().info("LED panel node has been started")

    def publish_led_states(self):
        msg = LedStateArray()
        msg.led_states = self.led_states_
        self.led_states_publisher_.publish(msg)

    def callback_set_led(self, request, response):
        led_number = request.led_number
        state = request.state

        if led_number > len(self.led_states_) or led_number <= 0:
            response.success = False
            return response
        if state not in [0, 1]:
            response.success = False
            return response

        self.led_states_[led_number - 1] = state
        response.success = True
        self.publish_led_states()          # publish the change straight away
        return response


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(LedPanelNode())
    rclpy.shutdown()


if __name__ == "__main__":
    main()
Solution: battery.py
📄 my_py_pkg/battery.py
#!/usr/bin/env python3
from functools import partial
import rclpy
from rclpy.node import Node
from my_robot_interfaces.srv import SetLed


class BatteryNode(Node):
    def __init__(self):
        super().__init__("battery")
        self.battery_state_ = "full"
        self.last_change_ = self.now_seconds()
        self.set_led_client_ = self.create_client(SetLed, "set_led")
        self.battery_timer_ = self.create_timer(0.1, self.check_battery_state)
        self.get_logger().info("Battery node has been started")

    def now_seconds(self):
        return self.get_clock().now().nanoseconds / 1e9

    def check_battery_state(self):
        time_now = self.now_seconds()
        if self.battery_state_ == "full" and time_now - self.last_change_ > 4.0:
            self.battery_state_ = "empty"
            self.get_logger().info("Battery is empty! Charging battery...")
            self.last_change_ = time_now
            self.call_set_led_server(3, 1)
        elif self.battery_state_ == "empty" and time_now - self.last_change_ > 6.0:
            self.battery_state_ = "full"
            self.get_logger().info("Battery is now full again.")
            self.last_change_ = time_now
            self.call_set_led_server(3, 0)

    def call_set_led_server(self, led_number, state):
        if not self.set_led_client_.service_is_ready():
            self.get_logger().warn("LED panel not available")
            return
        request = SetLed.Request()
        request.led_number = led_number
        request.state = state
        future = self.set_led_client_.call_async(request)
        future.add_done_callback(partial(self.callback_set_led, led_number=led_number, state=state))

    def callback_set_led(self, future, led_number, state):
        try:
            self.get_logger().info(f"LED {led_number} -> {state}: success={future.result().success}")
        except Exception as e:
            self.get_logger().error(f"Service call failed {e!r}")


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(BatteryNode())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

1

Why: hard-coded numbers don't survive the real world

Look at the nodes you wrote: self.number_ = 2, create_timer(0.5, …), self.robot_name_ = "LIMO". To change any of them you edit the code (and for C++, recompile). Now imagine the self-driving car: the cruise-control code is the same in Lahore traffic, on the M2 motorway and in a car park, but the maximum speed and following distance are not. You don't want three copies of the code. You want one program with knobs.

2

Picture it: the settings menu of a car

🎛️

Parameters are the settings menu of a car. The engine and the software (the code) are the same in every car of the model. The owner picks eco or sport mode, sets the speed limiter, chooses the cruise-control distance (the parameters). The factory sets defaults; you can change them before you drive, and some even while you drive.

A parameter's value can come from three places. The later one wins:

① in the codeThe defaultdeclare_parameter("max_speed", 50.0)
max_speed = 50.0
② at startupA command or a YAML file--ros-args -p max_speed:=110.0
--params-file motorway.yaml
max_speed = 110.0
③ while runningFrom the terminal or another noderos2 param set /adaptive_cruise max_speed 90.0
max_speed = 90.0 only used if the node listens: Lab 7
3

The rules of a parameter

📌 Properties of a parameter
  • A parameter belongs to one node. Two nodes can each have a max_speed; they are different parameters.
  • It has a name, a type and a value. Types: bool, int, double, string, and lists of each (plus byte[]).
  • A node must declare it before using it, with a default value. The default fixes the type: 2 is an int, 2.0 is a double.
  • It is set at startup (-p, YAML) or while running (ros2 param set). The node reads it with get_parameter("name").value.
  • Under the hood, every node offers parameter services (/node/get_parameters, /node/set_parameters, …). You'll list them in Lab 6: parameters are built on the services you learned in Lecture 4.
4

Try it: tune the adaptive cruise control

Your car follows another car. max_speed, safe_distance and driving_mode are parameters of the adaptive_cruise node. Change them while it drives, restart it with a different YAML file, and find out why a parameter callback matters.

2Add a parameter callback (click the highlighted parts)
📄 my_py_pkg/number_publisher.py (new parts)
from rcl_interfaces.msg import SetParametersResult
...
        self.number_timer_ = self.create_timer(
            1.0 / self.publish_frequency_, self.publish_number)
        self.add_on_set_parameters_callback(self.callback_parameters)
        self.get_logger().info("Number publisher has been started")

    def callback_parameters(self, params):
        for param in params:
            if param.name == "publish_frequency" and param.value <= 0.0:
                return SetParametersResult(

            if param.name == "number_to_publish":

                self.number_timer_ = self.create_timer(
                    1.0 / param.value, self.publish_number)
                self.get_logger().info(f"publish_frequency is now {param.value} Hz")
        return SetParametersResult(successful=True)

The speed limiter (a school zone for turtles)

Self-driving cars have a speed limiter between the planner and the motors. Build one for turtlesim: a node speed_limiter subscribes to cmd_vel_raw (geometry_msgs/msg/Twist), clamps linear.x to ±max_speed (default 1.0) and angular.z to ±max_turn (default 1.5), and publishes on turtle1/cmd_vel. Both limits must change live, and negative values must be refused.

flowchart LR K(["turtle_teleop_key"]) -- "/cmd_vel_raw" --> L(["speed_limiter
max_speed, max_turn"]) -- "/turtle1/cmd_vel" --> T(["turtlesim"])
💻 Test it
ros2 run turtlesim turtlesim_node
ros2 run my_py_pkg speed_limiter
ros2 run turtlesim turtle_teleop_key --ros-args -r turtle1/cmd_vel:=cmd_vel_raw

ros2 param set /speed_limiter max_speed -1.0         # must be refused
Solution
📄 my_py_pkg/speed_limiter.py
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from rcl_interfaces.msg import SetParametersResult


def clamp(value, limit):
    return max(-limit, min(limit, value))


class SpeedLimiterNode(Node):
    def __init__(self):
        super().__init__("speed_limiter")
        self.declare_parameter("max_speed", 1.0)     # m/s
        self.declare_parameter("max_turn", 1.5)      # rad/s
        self.max_speed_ = self.get_parameter("max_speed").value
        self.max_turn_ = self.get_parameter("max_turn").value
        self.add_on_set_parameters_callback(self.callback_parameters)
        self.cmd_publisher_ = self.create_publisher(Twist, "turtle1/cmd_vel", 10)
        self.cmd_subscriber_ = self.create_subscription(
            Twist, "cmd_vel_raw", self.callback_cmd, 10)
        self.get_logger().info(f"Speed limiter ready: max {self.max_speed_} m/s")

    def callback_cmd(self, msg):
        msg.linear.x = clamp(msg.linear.x, self.max_speed_)
        msg.angular.z = clamp(msg.angular.z, self.max_turn_)
        self.cmd_publisher_.publish(msg)

    def callback_parameters(self, params):
        for p in params:
            if p.name in ("max_speed", "max_turn") and p.value < 0.0:
                return SetParametersResult(successful=False, reason=f"{p.name} must be >= 0")
        for p in params:
            if p.name == "max_speed":
                self.max_speed_ = p.value
            elif p.name == "max_turn":
                self.max_turn_ = p.value
            self.get_logger().info(f"{p.name} is now {p.value}")
        return SetParametersResult(successful=True)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(SpeedLimiterNode())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

Add <depend>geometry_msgs</depend> to my_py_pkg/package.xml. Teleop sends 2.0 m/s per key press; with max_speed = 0.3 the turtle crawls. Same idea as a real car's speed limiter, with a standard message and two parameters.

CamelCase, starting with a capital, no underscores.

Five quick questions (5 min), then today's commands and homework.

Which three places do you touch to add a new .srv to an existing interfaces package?

Answer
Create the .srv file, add one line in rosidl_generate_interfaces, rebuild and source. (A new dependency also needs find_package, DEPENDENCIES and <depend>.)

Write a message Turtle.msg with a name and an x, y position.

Answer
string name / float64 x / float64 y. You'll use exactly this in Lecture 6.

A car's planner must run with max_speed 50 in the city and 110 on the motorway. Write the two start commands.

Answer
ros2 run my_car planner --ros-args -p max_speed:=50.0 and … -p max_speed:=110.0, or one YAML file per place with --params-file.

Write the YAML file that sets robot_name to "WALL-E" for the node robot_news_station.

Answer
/robot_news_station: →   ros__parameters: →     robot_name: "WALL-E"

What must a parameter callback return, and what happens if successful is False?

Answer
A SetParametersResult. With successful=False the change is refused, the old value stays, and the reason is shown to whoever tried to set it.
