Assignments & Capstone  ·  10 + 30 Marks

Assignments

Four graded assignments track the concept arc; the two-part capstone is where it all comes together — first in simulation, then on a robot you built yourself.
A1–A4 + quizzes: 10 marks
Capstone: 30 marks
Submit: course Git repo + PDF report
📦 Submission rules (all assignments)

Push your ROS 2 package(s) to your course Git repository under assignments/aN/, and upload a short PDF report (2–4 pages: what you built, commands to run it, screenshots/plots, what broke and how you fixed it).

Every package must build clean with colcon build on Ubuntu 22.04 + ROS 2 Humble and run with the exact command(s) listed in your report.

Include a one-line AI-use note. Late policy and integrity rules: see the Syllabus.

Three sections: the dates below are the Section B (Monday) session. Sections A & C are issued and due on the Thursday of the same week — the assignment is always issued in one week's session and due at the start of the next week's session for that section.

A1 — Workspace & a Python drive node Wk 3 → Wk 4

Objective (CLO1, CLO2): stand up a clean ROS 2 workspace and write your first node that commands the robot.

Tasks:

  1. Create ~/limo_ws with a package limo_drive (ament_python).
  2. Write a node square_driver that publishes geometry_msgs/Twist on /cmd_vel to drive LIMO in a 1 m × 1 m square, then stops.
  3. Expose side_length and linear_speed as ROS parameters.
  4. Add a launch file that starts Gazebo + your node; demonstrate the same node in differential and Ackermann modes and note the difference.

Deliverable: the limo_drive package + report with a screen recording link or a plot of the path from /odom.

A2 — URDF/Xacro extension & the TF tree Wk 5 → Wk 6

Objective (CLO3): modify a real robot description and reason about frames.

Tasks:

  1. Fork limo_description; add a new sensor link (e.g. a forward-facing ultrasonic or a second camera) as a Xacro macro with a fixed joint.
  2. Give it correct <origin>, <inertial>, and a visual mesh or primitive.
  3. Launch robot_state_publisher + RViz; capture ros2 run tf2_tools view_frames output showing your link in the tree.
  4. Write a static_transform_publisher (in a launch file) for a bonus off-body frame and explain when a static vs dynamic transform is correct.

Deliverable: modified description package + frames.pdf + report explaining the map → odom → base_link chain for LIMO.

A3 — Reactive perception Wk 7 → Wk 8

Objective (CLO5): turn raw sensor streams into behaviour.

Tasks:

  1. Node safe_stop: subscribe to /scan, stop and rotate away when an obstacle is within a configurable distance in the front arc.
  2. Node colour_seeker: use cv_bridge + OpenCV HSV thresholding + contours to detect a coloured target in /camera/image_raw and publish its pixel centroid and area.
  3. Combine them: LIMO wanders, avoids obstacles, and slows when the target fills more than X% of the frame.

Deliverable: limo_perception package + report with annotated detection frames and a short clip of the combined behaviour in Gazebo.

A4 — DIY differential-drive driver node Wk 12 → Wk 13

Objective (CLO8): implement the kinematics that a driver node hides.

Tasks:

  1. Derive, by hand (show the working), the forward and inverse differential-drive kinematics for "Forge" given wheel radius and track width.
  2. Implement a node that takes /cmd_vel → per-wheel target velocities → serial command, and reads encoder counts → publishes nav_msgs/Odometry + the odom → base_link TF.
  3. Provide a bringup.launch.py that starts the driver + robot_state_publisher.
  4. Validate: commanded vs measured straight-line distance and a 360° spin, with the error reported.

Deliverable: forge_base package + derivation scan + validation table. Works fully as a simulation/bench exercise if you have no hardware.

🏆 Capstone Project 30 marks

The capstone is delivered in two parts. Part 1 is the simulated autonomous mission built in Lecture 10 — the dress rehearsal. Part 2 is the review of your own robot from the Lecture 12–14 build arc. One written report covers both; the final defence is during finals week.

Grading rubric

CriterionWeightLooking for
Technical difficulty & correctness30%Kinematics, TF, and the ROS graph are right; the autonomy stack is configured, not just launched
System integration & robustness25%Bringup is one command; recovers from a blocked path / lost localisation; no manual babysitting
Experimental rigour20%Quantified results — path error, success rate over repeated runs, map quality — not a single lucky take
Report clarity15%Someone else could reproduce your run from the report alone
Defence & presentation10%You can explain every node in your graph and defend your design choices

Extension bank (for higher grades / DIY build direction)

  • Navigation: dynamic obstacle avoidance with a moving actor; custom Nav2 behaviour-tree node; recovery-behaviour tuning.
  • Perception-driven autonomy: drive to a YOLO-detected object; visual servoing on a colour target; AprilTag docking.
  • Multi-sensor state estimation: add a second EKF instance (map frame) and compare localised vs dead-reckoned trajectories.
  • Hardware: get the DIY robot driving under Nav2 for real; add a second sensor; 3D-print and fit the cover.
  • Challenge tier: full sim-to-real transfer of the Lecture 10 mission onto LIMO or Forge.
