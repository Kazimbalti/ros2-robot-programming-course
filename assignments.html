Assignments & Capstone  ·  10 + 30 Marks

Assignments

Each assignment grows out of the hands-on activities you already start in class, so you finish and polish them at home. The two-part capstone brings it all together: first the "Catch Them All" turtlesim project, then the "LIMO Delivery" mission on the LIMO.
A1–A4 + quizzes: 10 marks
Capstone: 30 marks
Submit: course Git repo + PDF report
📦 Submission rules (all assignments)

Push your ROS 2 package(s) to your course Git repository under assignments/aN/, and upload a short PDF report (2–4 pages: what you built, commands to run it, screenshots, what broke and how you fixed it).

Every package must build cleanly with colcon build on Ubuntu 22.04 + ROS 2 Humble and run with the exact command(s) listed in your report.

Include a one-line AI-use note. Late policy and integrity rules: see the Syllabus.

Three sections: the dates below are the Section B (Monday) session. Sections A & C are issued and due on the Thursday of the same week. An assignment is always issued in one week's session and due at the start of the next week's session for that section.

A1 — Workspace & a Python drive node Wk 3 → Wk 4 · completed

Objective (CLO1): set up a working ROS 2 workspace and command the LIMO from a first node. This assignment was issued and marked before the course was restructured; it is unchanged.

A2 — Topics & services: the resettable number counter Wk 6 → Wk 7

Objective (CLO2): write publishers, subscribers, a service server and a non-blocking client. Builds on Activity 3.1 and Activity 4.1.

Tasks:

  1. In my_py_pkg: number_publisher (publishes on /number) and number_counter (adds each number and publishes the total on /number_count).
  2. Add a /reset_counter service (example_interfaces/srv/SetBool) to the counter.
  3. Write a client node counter_supervisor that subscribes to /number_count and calls /reset_counter (non-blocking, with call_async + a done callback) whenever the total goes above 50.
  4. Show the system in rqt_graph and prove it works with ros2 topic echo /number_count.

Deliverable: the package + report with the rqt_graph screenshot and a terminal capture of the count rising and resetting.

A3 — Custom interfaces + launch: the smart LED panel Wk 8 → Wk 9

Objective (CLO3): design your own msg/srv and configure a multi-node system with parameters and one launch file. Builds on Activity 5.1 and Lecture 6.

Tasks:

  1. In my_robot_interfaces: LedStateArray.msg and SetLed.srv; the led_panel and battery nodes working together.
  2. Make the panel's led_states and the battery's empty/full times (empty_after, full_after) parameters.
  3. Write led_system.launch.py in my_robot_bringup that starts the panel with 5 LEDs and two battery nodes (renamed, each controlling a different LED, with different timings).
  4. Save the parameters to a YAML file and load them from the launch file.

Deliverable: both packages + report with ros2 interface show output, the YAML file and a capture of /led_states changing.

A4 — LIMO sensors: the safe red-object follower Wk 13 → Wk 14

Objective (CLO5): turn LiDAR and camera data into safe behaviour on the LIMO in Gazebo. Builds on Lectures 8, 10 and 11.

Tasks:

  1. In limo_lab: color_tracker (publishes the red object's horizontal error and area) and red_follower (searches, turns toward, and approaches the object).
  2. Add the LiDAR safety layer: never drive forward if anything is closer than a safety_distance parameter in the front ±20° sector.
  3. Make every driving node publish a zero Twist on exit (safe main() from Lecture 14).
  4. Test with the red box and an obstacle placed between the robot and the box; report what the robot does.

Deliverable: the limo_lab package + report with annotated camera/mask screenshots and a ≤60 s clip of the behaviour in Gazebo.

🏆 Capstone Project 30 marks

The capstone has two parts. Part 1 is the Catch Them All project from Lecture 7: everything from the ROS 2 Bootcamp in one system. Part 2 is the LIMO Delivery final mission, done in teams of 3–4 on the real LIMO (or in simulation if robot time is not available). One written report covers both.

General grading principles

CriterionWeightLooking for
It works40%The required behaviour happens, started with the documented command(s), without manual help
Correct ROS 2 design25%Sensible choice of topics vs services, clean interfaces, parameters instead of hard-coded values, one-command launch
Evidence15%Video, ros2 bag, rqt_graph, measured results rather than a single lucky run
Code quality & safety10%Readable, commented code; safe stop on exit; speed limits on the LIMO
Explanation10%Every team member can explain every node in the graph

Extensions (for higher grades)

  • Part 1: a second hunter turtle; a service that pauses and resumes spawning; a smoother controller (limit acceleration).
  • Part 2: patrol repeats until a red object is seen; the mission restarts from any station after a failure; waypoints loaded from a YAML file.
  • Perception: detect two colours and deliver to the right one; use the depth image to stop at an exact distance.
  • Challenge tier: the full Part 2 mission running on the physical LIMO with a map of the real lab.
