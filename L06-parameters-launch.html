6.1Launch files, step by step

1Picture it2The rules3Watch it4Try it5Remember it
1

Picture it: the car's start button

🔑

A launch file is the start button of a car. You press one button; the car starts the engine, the dashboard, the lights, the cameras and the driver-assist computer, in the right order, with the right settings. You don't start each part by hand.

🎬

Or a film director's call sheet. It lists every actor (node), the role they play (name=), who they talk to (remappings=) and their script notes (parameters=). "Action!" (ros2 launch) starts them all; "Cut!" (Ctrl+C) stops them all.

2

The rules of a launch file

📌 Five rules
  • A launch file is a Python file ending in .launch.py (XML and YAML also exist: section 6.2).
  • It must contain a function generate_launch_description() that returns a LaunchDescription: the list of things to start.
  • Each Node(package=…, executable=…) is exactly one ros2 run package executable.
  • Launch files live in the launch/ folder of a bringup package (my_robot_bringup), which must install that folder.
  • The bringup package lists every package it starts as an <exec_depend> in package.xml.

Everything you typed after --ros-args has a launch-file twin:

🏷️Rename the node-r __node:=front_lidarname="front_lidar"
🔀Remap a topic or service-r scan:=front/scanremappings=[("scan", "front/scan")]
🎛️Set a parameter-p max_speed:=50.0parameters=[{"max_speed": 50.0}]
📄Load a YAML file--params-file city.yamlparameters=[path_to_city_yaml]
📁Put it in a namespace-r __ns:=/car1namespace="car1"
🔊Log level--log-level debugarguments=["--ros-args", "--log-level", "debug"]
3

Watch it: what ros2 launch does

ros2 launch reads your file, calls generate_launch_description(), and starts one operating-system process per Node, each with its own pid. It collects their output in one terminal and, on Ctrl+C, stops every one of them.

⚠️ A launch file only starts nodes

The nodes still find each other by topic names, exactly as when you started them by hand. If the names don't match (a missing remap), the launch file starts everything and nothing talks. rqt_graph is still your best friend.

📄 my_robot_bringup/launch/number_app_args.launch.py
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.conditions import IfCondition
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    number_arg = DeclareLaunchArgument(
        "number", default_value="2",
        description="The number to publish")
    frequency_arg = DeclareLaunchArgument(
        "frequency", default_value="1.0",
        description="Messages per second (a float: 2.0, not 2)")
    graph_arg = DeclareLaunchArgument(
        "graph", default_value="false",
        description="Also open rqt_graph (true/false)")

    number_publisher_node = Node(
        package="my_py_pkg",
        executable="number_publisher",
        parameters=[{"number_to_publish": LaunchConfiguration("number"),
                     "publish_frequency": LaunchConfiguration("frequency")}],
    )

    number_counter_node = Node(package="my_py_pkg", executable="number_counter")

    rqt_graph_node = Node(
        package="rqt_graph",
        executable="rqt_graph",
        condition=IfCondition(LaunchConfiguration("graph")),
    )

    return LaunchDescription([
        number_arg, frequency_arg, graph_arg,
        number_publisher_node, number_counter_node, rqt_graph_node,
    ])

💡 Conditions with a calculation

IfCondition(PythonExpression([LaunchConfiguration("number"), " > 5"])) starts a node only if the number is bigger than 5. PythonExpression joins the pieces into Python code and evaluates it at launch time. Use it sparingly: simple true/false arguments are easier to read.

L4Lab 4 — Namespaces: many robots at once

LAB 4 · 25 min

Two robots, one launch file, no clashes

Goal: two copies of the number app run at the same time, as /robot1/… and /robot2/…, without seeing each other. Then two turtlesim windows, where one turtle copies the other.

1The idea: a namespace is a folder for names

Start number_publisher twice and both publish on /number: the counters can't tell the robots apart. A namespace puts a prefix in front of every relative name in a node: its topics, its services, and the node's own name.

/robot1+number=/robot1/number
In the codeKindNamespace robot1 makes itSelf-driving example
"number"relative/robot1/number"scan" → /car1/scan
"/number"absolute (starts with /)/number: unchanged!"/traffic_lights": shared by all cars
"~/status"private (~ = the node)/robot1/number_publisher/status/car1/lidar_driver/status
node number_publishernode name/robot1/number_publisher/car1/planner
⚠️ Write relative names in your nodes

Since Lecture 3 you wrote create_publisher(Int64, "number", 10), without a /. That is exactly why your nodes can be put in a namespace. A node that publishes on "/number" ignores namespaces and every robot would publish on the same topic.

2The same in a launch file

from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    ld = LaunchDescription()
    for ns, number in [("robot1", 1), ("robot2", 2)]:
        ld.add_action(Node(package="my_py_pkg", executable="number_publisher",
                           namespace=ns,
                           parameters=[{"number_to_publish": number}]))
        ld.add_action(Node(package="my_py_pkg", executable="number_counter",
                           namespace=ns))
    return ld

3A whole robot in a namespace: GroupAction + PushRosNamespace

Writing namespace= on every node of a car is repetitive and easy to forget. Group the nodes and push the namespace once:

📄 my_robot_bringup/launch/two_robots.launch.py (version 2)
from launch import LaunchDescription
from launch.actions import GroupAction
from launch_ros.actions import Node, PushRosNamespace


def robot(ns, number):
    return GroupAction([
        PushRosNamespace(ns),
        Node(package="my_py_pkg", executable="number_publisher",
             parameters=[{"number_to_publish": number}]),
        Node(package="my_py_pkg", executable="number_counter"),
    ])


def generate_launch_description():
    return LaunchDescription([robot("robot1", 1), robot("robot2", 2), robot("robot3", 3)])

from launch.events import Shutdown
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(package="turtlesim", executable="turtlesim_node")

The cylinder calculator

Volume = π · r² · h    Surface area = 2 · π · r · (r + h)

(asks the user)"]) --> R[["/radius"]] & H[["/height"]] R --> SQ(["radius_squarer"]) --> R2[["/radius_squared"]] R --> C(["cylinder_calc"]) H --> C R2 --> C C --> CY[["/cylinder

  2. radius_squarer: subscribes to /radius and publishes r² on /radius_squared.
  3. cylinder_calc: subscribes to all three topics. When it has all three values, it publishes a custom my_robot_interfaces/msg/Cylinder (float64 volume, float64 surface_area) on /cylinder.

Solution: cylinder_calc.py (the other two nodes follow patterns you already know)
📄 my_py_pkg/my_py_pkg/cylinder_calc.py
#!/usr/bin/env python3
from math import pi
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64
from my_robot_interfaces.msg import Cylinder


class CylinderCalcNode(Node):
    def __init__(self):
        super().__init__("cylinder_calc")
        self.radius_ = None
        self.radius_squared_ = None
        self.height_ = None
        self.create_subscription(Float64, "radius", self.callback_radius, 10)
        self.create_subscription(Float64, "radius_squared", self.callback_radius_squared, 10)
        self.create_subscription(Float64, "height", self.callback_height, 10)
        self.cylinder_pub_ = self.create_publisher(Cylinder, "cylinder", 10)

    def callback_radius(self, msg):
        self.radius_ = msg.data
        self.calculate()

    def callback_radius_squared(self, msg):
        self.radius_squared_ = msg.data
        self.calculate()

    def callback_height(self, msg):
        self.height_ = msg.data
        self.calculate()

    def calculate(self):
        if None in (self.radius_, self.radius_squared_, self.height_):
            return                                   # wait until we have all three
        msg = Cylinder()
        msg.volume = pi * self.radius_squared_ * self.height_
        msg.surface_area = 2 * pi * (self.radius_ * self.height_ + self.radius_squared_)
        self.cylinder_pub_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(CylinderCalcNode())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

Remember: add "msg/Cylinder.msg" to the interfaces CMakeLists, add <depend>std_msgs</depend> to my_py_pkg/package.xml, and register three executables. Check: with r = 2 and h = 5 you should get volume ≈ 62.83 and surface area ≈ 87.96.

QoS: how carefully is each message delivered?

📻

Reliability: live radio or registered mail? A LiDAR sends 10 scans a second. If one is lost over Wi-Fi, resending it is pointless: the next one is already newer. That's best effort, like live radio. A "stop the car" command must arrive, even late: reliable, like registered mail that is re-sent until signed for.

📌

Durability: a shout or a notice board? A map is published once. A node that starts later would miss a shout (volatile). With transient_local the publisher keeps the last message pinned on a notice board, and late joiners read it straight away.

📌 The rules of QoS (Quality of Service)
  • Every publisher and subscriber has a QoS profile: history (keep the last N), depth (N), reliability, durability (and a few advanced ones: deadline, lifespan, liveliness).
  • The 10 you have written since Lecture 3 in create_publisher(Int64, "number", 10) is a QoS profile: keep the last 10, reliable, volatile.
  • The publisher offers, the subscriber requests. If the request is stricter than the offer, they don't connect, with only a warning.
Publisher offersSubscriber requestsResultSelf-driving example
reliablereliable✔ connected, lost messages re-sent/emergency_stop
reliablebest_effort✔ connected, works as best efforta dashboard that only wants the latest speed
best_effortbest_effort✔ connected, losses are not re-sent/camera/image_raw, /scan
best_effortreliable✖ no connectionRViz showing no LiDAR points (Lecture 9 tip!)
transient_localvolatile or transient_local✔ (only transient_local subscribers get old messages)/map, the robot description
volatiletransient_local✖ no connection

💻 Terminal 1: a "LiDAR" that publishes best effort
ros2 topic pub -r 2 --qos-reliability best_effort /fake_scan std_msgs/msg/String "{data: 'scan'}"
💻 Terminal 2: a reliable subscriber
ros2 topic echo --qos-reliability reliable /fake_scan
✅ You should see
[WARN] [ros2cli_…]: New publisher discovered on topic '/fake_scan', offering incompatible QoS. No messages will be received from it. Last incompatible policy: RELIABILITY
💻 Terminal 2: fix it, then inspect
ros2 topic echo --qos-reliability best_effort /fake_scan
ros2 topic info -v /fake_scan        # shows Reliability: BEST_EFFORT on the publisher
2A message pinned for late joiners (transient_local)
💻 Terminal 1: a "map" published every 20 s
ros2 topic pub -r 0.05 --qos-reliability reliable --qos-durability transient_local \
  /fake_map std_msgs/msg/String "{data: 'the map'}"
💻 Terminal 2: join late, twice
ros2 topic echo --qos-durability transient_local --qos-reliability reliable /fake_map   # instant
ros2 topic echo --qos-durability volatile --qos-reliability reliable /fake_map          # waits up to 20 s

The first echo prints data: the map immediately; the second has to wait for the next publication. That is why RViz shows the map at once in Lecture 12.

✅ Knowledge checkLecture 6 check: 10 questions

Which function must every Python launch file contain?

ros2 launch calls exactly this function and starts what it returns.

You created launch/radio.launch.py, but ros2 launch says the file was not found. Most likely?

A new file is installed only by a build; --symlink-install spares you rebuilds for edits only.

In a launch file, how do you do -r __node:=station_x?

name= renames the node; namespace= adds a prefix.

You run ros2 launch my_robot_bringup number_app_args.launch.py frequency:=3 and the node stops with InvalidParameterTypeException. Why?

Same rule as Lecture 5: write frequency:=3.0.

Why can't you write if LaunchConfiguration("graph") == "true": in a launch file?

LaunchConfiguration is a placeholder (a substitution), not the value.

A node publishes on "/cmd_vel" and is started with namespace="car2". Which topic does it use?

Only relative names (no leading /) get the namespace. Write "cmd_vel".

What does respawn=True do?

After respawn_delay seconds, with a new pid and fresh variables.

The LiDAR publishes /scan best effort. Your subscriber uses the default 10 (reliable). What happens?

A reliable request can't be served by a best-effort offer. Use qos_profile_sensor_data.

Two teams' LIMOs react to each other's /cmd_vel. The quickest fix?

Each domain is a separate ROS world.

Your node's debug messages never appear. Why?

Each node shows its level and everything more serious.

6.6Exit ticket & homework

Five quick questions (5 min), then today's commands and homework.

Write the Node(...) for robot_news_station named station_x with robot_name = "X".

Answer
Node(package="my_py_pkg", executable="robot_news_station", name="station_x", parameters=[{"robot_name": "X"}])

Which two lines in the bringup package make ros2 launch find your launch and YAML files?

Answer
install(DIRECTORY launch config DESTINATION share/${PROJECT_NAME}) in CMakeLists.txt, and in the launch file get_package_share_directory("my_robot_bringup") (or FindPackageShare) to find them.

Declare a launch argument use_sim_time (default false) and pass it to a node.

Answer
DeclareLaunchArgument("use_sim_time", default_value="false") and Node(…, parameters=[{"use_sim_time": LaunchConfiguration("use_sim_time")}]).

The node publishes "scan". With PushRosNamespace("car1"), what is the full topic name, and what is it with a publisher on "/scan"?

Answer
/car1/scan, and /scan (absolute names are not changed).

Which QoS settings suit (a) a camera stream, (b) a map published once, (c) an emergency stop?

Answer
(a) best effort, volatile (qos_profile_sensor_data). (b) reliable, transient_local. (c) reliable.
