What does source /opt/ros/humble/setup.bash do?

Answer
It loads ROS 2 into this terminal, so commands like ros2 work. Every new terminal needs it, which is why we put it in ~/.bashrc.

Which command starts the turtlesim window?

Answer
ros2 run turtlesim turtlesim_node. The pattern is ros2 run <package> <executable>.

What does chmod +x file.py do?

Answer
It makes the file executable (allowed to run as a program).

2.1The idea in 10 minutes

👨‍🍳

Think of a restaurant kitchen. Each chef does one job: one cuts vegetables, one grills, one makes sauce. They pass food to each other. The chefs work at stations, and all stations sit inside one kitchen.

In ROS 2: a chef = node, a station = package, and the kitchen = workspace.

A robot program is not one giant file. It is split into small programs called nodes. On a mobile robot you might have a camera node, a LiDAR node, a motor-driver node and a navigation node. Each does one thing, and they talk to each other.

flowchart LR subgraph WS["🏠 Workspace: ~/ros2_ws"] subgraph P1["📦 Package: camera_pkg"] N1(["camera driver node"]) --> N2(["image processing node"]) end subgraph P2["📦 Package: motion_planning_pkg"] N3(["motion planning node"]) --> N4(["path correction node"]) end subgraph P3["📦 Package: hardware_control_pkg"] N5(["main control loop node"]) --> N6(["motor driver node"]) end end N2 --> N3 N4 --> N5
📌 Four words to remember
  • Node — a small program with one job. Nodes talk to each other through topics, services and parameters.
  • Package — a folder that holds related nodes. It is the unit you build and share (for example, one package for the camera, one for the wheels).
  • Workspace — the folder that holds your packages. You build everything in it with one command.
  • colcon — the build tool. colcon build turns your src/ into something ROS 2 can run.

Where does your Python code sit?

You write Python and call the rclpy library. Under the hood, rclpy (Python) and rclcpp (C++) both use the same C library, rcl, which talks to DDS, the middleware that actually moves data between nodes. That is why a Python node and a C++ node can talk to each other.

flowchart TB A["Your node (Python)"] --> B["rclpy"] C["Your node (C++)"] --> D["rclcpp"] B --> E["rcl (core C library)"] D --> E E --> F["DDS middleware: moves the data"]

4Create a Python package

Packages are always created inside src/.

💻 Terminal
cd ~/ros2_ws/src
ros2 pkg create my_py_pkg --build-type ament_python --dependencies rclpy

This is what you get. Learn the three files marked ⭐, because you will edit them all the time:

my_py_pkg/ ├── my_py_pkg/ ⭐ your Python node files go HERE (the inner folder) │ └── __init__.py ├── package.xml ⭐ name, description, dependencies ├── setup.py ⭐ where you register executables ├── setup.cfg ├── resource/my_py_pkg └── test/
5Build only your package

Always build from the workspace root (~/ros2_ws), never from inside src/.

💻 Terminal
cd ~/ros2_ws
colcon build --packages-select my_py_pkg
✅ You should see
Starting >>> my_py_pkg
Finished <<< my_py_pkg [1.1s]
Summary: 1 package finished
💡 A yellow "SetuptoolsDeprecationWarning"?

That is harmless on Humble, and your package still built. If you want to silence it: pip3 install setuptools==58.2.0.

L2Lab 2 — Write your first node

LAB 2 · 45 min

Hello ROS 2, then a node with a timer

Goal: run ros2 run my_py_pkg py_node and see your own message printed every half second.

1Create the file in the inner package folder
💻 Terminal
cd ~/ros2_ws/src/my_py_pkg/my_py_pkg
touch my_first_node.py
chmod +x my_first_node.py
code ~/ros2_ws

The last line opens the whole workspace in VS Code.

2Type the smallest possible node
📄 my_py_pkg/my_first_node.py
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node


def main(args=None):
    rclpy.init(args=args)                   # 1. start ROS 2 communication
    node = Node("py_test")                  # 2. create a node called py_test
    node.get_logger().info("Hello ROS2")    # 3. print a log message
    rclpy.spin(node)                        # 4. keep the node alive until Ctrl+C
    rclpy.shutdown()                        # 5. clean up


if __name__ == "__main__":
    main()

Every ROS 2 Python program follows these five steps: init → create node → do work → spin → shutdown.

3Register it as an executable in setup.py

ROS 2 only runs files that you have listed here. Add the highlighted line inside console_scripts:

📄 my_py_pkg/setup.py (bottom of the file)
    entry_points={
        'console_scripts': [
            "py_node = my_py_pkg.my_first_node:main",
        ],
    },

Read it as: "the command py_node runs the main function in my_py_pkg/my_first_node.py".

4Build, source, run
💻 Terminal
cd ~/ros2_ws
colcon build --packages-select my_py_pkg --symlink-install
source ~/.bashrc
ros2 run my_py_pkg py_node
✅ You should see
[INFO] [1727700000.123456789] [py_test]: Hello ROS2

The program keeps running because of spin. Press Ctrl+C to stop it.

🏷️ Three names, three different things
  • my_first_node.py — the file name
  • py_test — the node name (what ros2 node list shows)
  • py_node — the executable name (what you type after ros2 run)
⚡ Why --symlink-install?

It links to your Python file instead of copying it. After this, editing the Python file needs no rebuild. You still rebuild when you add a new executable in setup.py.

5Upgrade to the object-oriented (OOP) style with a timer

Real nodes are written as a class. Replace the whole file with this:

📄 my_py_pkg/my_first_node.py
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node


class MyNode(Node):

    def __init__(self):
        super().__init__("py_test")
        self.counter_ = 0
        self.get_logger().info("Hello ROS2")
        self.create_timer(0.5, self.timer_callback)   # call every 0.5 s

    def timer_callback(self):
        self.counter_ += 1
        self.get_logger().info("Hello " + str(self.counter_))


def main(args=None):
    rclpy.init(args=args)
    node = MyNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()
💻 Terminal (no rebuild needed, thanks to --symlink-install)
ros2 run my_py_pkg py_node
✅ You should see a new line every 0.5 s
[INFO] [...] [py_test]: Hello ROS2
[INFO] [...] [py_test]: Hello 1
[INFO] [...] [py_test]: Hello 2
[INFO] [...] [py_test]: Hello 3

🔍 What each line does

CodeMeaning
class MyNode(Node)Your node is a ROS 2 Node, so it gets all of Node's abilities (logger, timers, publishers…).
super().__init__("py_test")Gives the node its name.
self.counter_ = 0A variable that belongs to the node. It remembers its value between callbacks.
create_timer(0.5, f)"Call function f every 0.5 seconds." A timer is how a node does something repeatedly.
timer_callbackA callback is a function that ROS 2 calls for you when something happens (here: the timer fires).
rclpy.spin(node)Waits and runs callbacks. Without spin, the timer would never fire.

➕ Going further (optional): the same node in C++

Python is our main language, but ROS 2 is multi-language. If you know C++, try this.

💻 Terminal
cd ~/ros2_ws/src
ros2 pkg create my_cpp_pkg --build-type ament_cmake --dependencies rclcpp
touch my_cpp_pkg/src/my_first_node.cpp
📄 my_cpp_pkg/src/my_first_node.cpp
#include "rclcpp/rclcpp.hpp"

class MyNode : public rclcpp::Node
{
public:
    MyNode() : Node("cpp_test"), counter_(0)
    {
        RCLCPP_INFO(this->get_logger(), "Hello Cpp Node");
        timer_ = this->create_wall_timer(std::chrono::seconds(1),
                                         std::bind(&MyNode::timerCallback, this));
    }

private:
    void timerCallback()
    {
        counter_++;
        RCLCPP_INFO(this->get_logger(), "Hello %d", counter_);
    }
    rclcpp::TimerBase::SharedPtr timer_;
    int counter_;
};

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<MyNode>();
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}

Add these lines to my_cpp_pkg/CMakeLists.txt, just before ament_package():

📄 my_cpp_pkg/CMakeLists.txt
add_executable(cpp_node src/my_first_node.cpp)
ament_target_dependencies(cpp_node rclcpp)

install(TARGETS
  cpp_node
  DESTINATION lib/${PROJECT_NAME}
)
💻 Terminal
cd ~/ros2_ws
colcon build --packages-select my_cpp_pkg
source ~/.bashrc
ros2 run my_cpp_pkg cpp_node

In C++, every code change needs a rebuild. For VS Code IntelliSense, add /opt/ros/humble/include/** to the include path (Ctrl+Shift+P, then "C/C++: Edit Configurations").

ROS 2 adds some publishers and services to every node automatically. Your own ones will appear here in the next lectures.

2Run the same executable three times under different names

Stop Terminal 1 first. Then open three terminals (Terminator: Ctrl+Shift+E / O splits the window).

💻 Terminal 1
ros2 run my_py_pkg py_node --ros-args --remap __node:=abc
💻 Terminal 2
ros2 run my_py_pkg py_node --ros-args --remap __node:=xyz

ros2 node list
✅ You should see
/abc
/xyz
⚠️ Two nodes with the same name

ROS 2 lets you start them, but prints a warning and the tools get confused. Every node in a system should have a unique name. Renaming at runtime is how you run one program several times.

3See the graph with rqt_graph

Keep /abc and /xyz running.

💻 Terminal 3
rqt_graph

A window opens and shows your nodes. They are not connected yet, because they don't talk to each other. You will see arrows between nodes from Lecture 3 onwards. Close the window and stop all nodes with Ctrl+C.

A node that introduces you

In my_py_pkg, create student_node.py starting from the template. The node must be named student and, every 1 second, print "Hi, I am <your name>, message <n>". Register it as the executable hello_me. Then run it twice at the same time, with the node names student_a and student_b.

Hint
You need a new line in setup.py, then a rebuild because it's a new executable. Use --ros-args --remap __node:=student_a.
Solution
📄 my_py_pkg/student_node.py
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node


class StudentNode(Node):
    def __init__(self):
        super().__init__("student")
        self.count_ = 0
        self.create_timer(1.0, self.say_hi)

    def say_hi(self):
        self.count_ += 1
        self.get_logger().info(f"Hi, I am Ali, message {self.count_}")


def main(args=None):
    rclpy.init(args=args)
    node = StudentNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()

✅ Knowledge checkLecture 2 check: 5 questions

Which folder do you edit by hand?

Only src/. The other three are generated by colcon build and can be deleted safely.

You added a new executable to setup.py. What must you do before ros2 run finds it?

--symlink-install only saves rebuilds when you edit Python files. New executables need a build and a source.

What does rclpy.spin(node) do?

Without spin the program ends immediately and timers or subscribers never run.

Which name appears in ros2 node list for super().__init__("py_test")?

The node name comes from super().__init__(). py_node is the executable and MyNode is only the class.

How do you run the same executable twice without a name clash?

Renaming at runtime is how one program runs many times.

2.4Exit ticket (5 min)

Which folder do you edit: src, build, install or log?

Answer
Only src. The others are generated by colcon build.

In "py_node = my_py_pkg.my_first_node:main", which part do you type after ros2 run my_py_pkg?

Answer
py_node, the executable name.

What happens if you remove rclpy.spin(node) from the OOP node?

Answer
The program ends immediately. The timer callback never runs, because nothing is waiting for it.

You edited a Python file and built with --symlink-install. Do you need to rebuild?
