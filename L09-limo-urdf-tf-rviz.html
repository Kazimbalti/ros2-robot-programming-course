9.0Warm-up (5 min)

The LIMO's LiDAR sees a wall 1 m straight ahead of the LiDAR. Is the wall also 1 m ahead of the robot's centre?

Answer
No. The LiDAR is about 10 cm in front of the centre, so the wall is about 1.1 m from the centre. To combine data from different parts we need to know where each part is. That's today.

Which topic tells us where the robot is relative to its start?

Answer
/odom. Today you'll see that the same information is also in TF, as the transform odom → base_link.

9.1The idea in 10 minutes

🦴

URDF is the robot's skeleton written on paper. Links are the bones (rigid parts: chassis, wheel, LiDAR). Joints connect two links and say how they can move (fixed, continuous for wheels, revolute for steering).

TF is a live GPS for every bone. Every link has its own coordinate frame. TF keeps the whole tree of frames up to date, many times per second, so any node can ask "where is the LiDAR relative to the map, right now?".

RViz is the robot's eyes on your screen. It draws the model, the frames and the sensor data, all placed correctly using TF.

LAB 1 · 35 min

mini_bot.urdf: a box, a LiDAR and two wheels

1Write the URDF
💻 Terminal
mkdir -p ~/ros2_ws/urdf && code ~/ros2_ws/urdf/mini_bot.urdf
📄 ~/ros2_ws/urdf/mini_bot.urdf
<?xml version="1.0"?>
<robot name="mini_bot">

  <!-- LINK 1: the chassis. Its frame is the robot centre. -->
  <link name="base_link">
    <visual>
      <geometry><box size="0.4 0.25 0.1"/></geometry>
      <material name="blue"><color rgba="0.2 0.3 0.9 1"/></material>
    </visual>
  </link>

  <!-- LINK 2: the LiDAR, bolted on top, 12 cm forward -->
  <link name="lidar_link">
    <visual>
      <geometry><cylinder radius="0.05" length="0.05"/></geometry>
      <material name="black"><color rgba="0.1 0.1 0.1 1"/></material>
    </visual>
  </link>
  <joint name="base_to_lidar" type="fixed">
    <parent link="base_link"/>
    <child link="lidar_link"/>
    <origin xyz="0.12 0 0.075" rpy="0 0 0"/>
  </joint>

  <!-- LINKS 3 + 4: wheels that can spin forever (continuous) about their y axis -->
  <link name="left_wheel_link">
    <visual>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry><cylinder radius="0.06" length="0.04"/></geometry>
      <material name="grey"><color rgba="0.5 0.5 0.5 1"/></material>
    </visual>
  </link>
  <joint name="base_to_left_wheel" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel_link"/>
    <origin xyz="0 0.15 -0.03" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
  </joint>

  <link name="right_wheel_link">
    <visual>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry><cylinder radius="0.06" length="0.04"/></geometry>
      <material name="grey"/>
    </visual>
  </link>
  <joint name="base_to_right_wheel" type="continuous">
    <parent link="base_link"/>
    <child link="right_wheel_link"/>
    <origin xyz="0 -0.15 -0.03" rpy="0 0 0"/>

</robot>

L5Lab 5 — TF from the terminal and from Python

LAB 5 · 25 min

Publish a frame; look one up

1Add a "front bumper" frame without touching the URDF
💻 Terminal 4
ros2 run tf2_ros static_transform_publisher --x 0.2 --y 0 --z 0 \
  --roll 0 --pitch 0 --yaw 0 --frame-id base_link --child-frame-id front_bumper

In RViz, the TF display now shows front_bumper 20 cm in front of the robot, and it moves with the robot. This is how you add a sensor that isn't in the URDF (for example a new camera on a real robot).

2Look up a transform in Python: where_am_i.py
📄 limo_lab/limo_lab/where_am_i.py
#!/usr/bin/env python3
import math
import rclpy
from rclpy.node import Node
from rclpy.time import Time
from tf2_ros import Buffer, TransformListener, TransformException


class WhereAmI(Node):
    def __init__(self):
        super().__init__("where_am_i")
        self.declare_parameter("target_frame", "odom")
        self.declare_parameter("source_frame", "base_link")
        self.target_ = self.get_parameter("target_frame").value
        self.source_ = self.get_parameter("source_frame").value
        self.tf_buffer_ = Buffer()                                 # stores recent transforms
        self.tf_listener_ = TransformListener(self.tf_buffer_, self)   # fills the buffer from /tf
        self.create_timer(1.0, self.on_timer)

    def on_timer(self):
        try:
            t = self.tf_buffer_.lookup_transform(self.target_, self.source_, Time())  # Time() = latest
        except TransformException as e:
            self.get_logger().warn(f"No transform yet: {e}")
            return
        p = t.transform.translation
        q = t.transform.rotation
        yaw = math.atan2(2.0 * (q.w * q.z + q.x * q.y), 1.0 - 2.0 * (q.y * q.y + q.z * q.z))
        self.get_logger().info(
            f"{self.source_} in {self.target_}: x={p.x:.2f} y={p.y:.2f} z={p.z:.2f} yaw={math.degrees(yaw):.0f} deg")


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(WhereAmI())
    rclpy.shutdown()


if __name__ == "__main__":
    main()

What is the difference between a link and a joint?

Answer
A link is a rigid part with its own frame. A joint connects a parent link to a child link and defines how the child can move.

Which joint type for (a) a wheel (b) a bolted-on LiDAR (c) a steering hinge with limits?

Answer
(a) continuous (b) fixed (c) revolute

Which node turns the URDF into TF?

Answer
robot_state_publisher

In ROS, which directions are x, y and z for a robot?

Answer
x forward, y left, z up.
